## 跨偶像复用边界与当前详情证据

实现目标是共用观察、机制比较、合法动作约束和回放链路；偶像身份、准确卡版本、装备和社区策略是数据输入。当前角色仅作为首个实机验收对象，不以角色名或固定出牌顺序代替机制推理。泛化验收应覆盖不同资源路线、行动返还/抽牌顺序、持续收益与末回合兑现，以及定制和重复副本；合成回放通过之后仍需其他角色实机验证。

`HIRO_EXAM_CARD_DETAILS=1` 为默认关闭的当前手牌详情观察入口：打开已识别的持有卡列表，按精确 ID/强化版本匹配唯一手牌，读取有选中框且详情身份一致的 OCR，关闭后核对原局面。列表顺序与实际手牌顺序不同，禁止按索引直接映射；同版本重复副本不作对应推断。观察失败不提供效果证据，无法返回原考试则停止出牌。

OCR 记录绑定当前决策截图及详情截图的像素哈希，进入 `public_info` 并随现有完整决策输入冻结；每次动作后重新读取，不创建跨回合的效果缓存。原始文字不是完整语义认证，图标、费用符号和跨行条件可能缺失，不覆盖 CardView 的主数据字段。CLI 与 API 使用同一份上下文。此功能补充通用观察能力，不等于已实现自动学习或跨角色胜率验证。

### 泛化与经验沉淀的验收边界

目标是机制驱动的通用决策器。角色身份用于找到真实专属卡与P道具，出牌顺序依据效果、成本、行动预算、资源增长和当前局面推导。角色专属效果可以不同，共用决策接口和执行器不随角色复制。

当前闭环：画面事实→合法动作→规则/模型比较→执行校验→冻结局面与结果。ExamMemory只保存本场记忆，不是训练；strategy_references读取版本化人工建议，没有自动从战果写回策略。

后续经验闭环按以下边界建设：

1. 从失败记录提取带适用条件的候选假设，记录原始局面、反例、未知条件和来源。一次失败不直接证明某个动作错误，一次成功不证明因果。
2. 以费用、触发、资源、行动返还、持续增长、一次性兑现等机制索引建议；不以偶像ID规定出牌表。候选建议默认不进入实机决策。
3. 同机制跨角色留出验证：专属卡和道具变化时仍从真实效果推理；仅改角色名字的Mock不能算跨角色验收。
4. 跨机制反例验证：好印象增长建议不得误用于仅干劲、好调或集中局面；不满足触发条件或信息未知时拒绝套用。
5. 固定输入与模型/提示版本进行回放，检查合法性、事实引用、资源账和行动顺序；离线模型改选不等于终局提升。
6. 通过回放后才受控实机，记录不同编成的过线率、得分、资源消耗和失败类型。晋级为可用建议时保留版本和回退点。

当前仍在首个机制的流程与识别验证阶段；尚不宣称自动学习或跨机制已可用。Codex CLI与API应共享同一局面和决策契约，适配器只负责模型调用，不承载角色打法。
