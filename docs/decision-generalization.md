# 决策泛化约束

目标是能适配、积累不同偶像卡版本和构筑的决策经验。先用白線リーリヤ验证端到端流程；单角色通关不等于通用决策验收。

## 分层边界

- 平台执行：Windows/Mac 只负责观察与合法输入，不包含角色打法。
- 通用机制：卡牌/饮料/道具效果、费用、触发条件、行动预算、持续时间和信息可信度。确定规则负责合法性与可证明的局部比较；缺少模拟器时不伪造收益预测。
- 策略资料：按机制路线、偶像卡版本与阶段组织目标、组合、保留条件和例外，记录来源与适用前提。角色资料作为上下文，不在执行器中写角色分支。同一角色不同卡版本不能混为一套打法。
- 决策接口：规则、模型或将来的搜索使用相同状态和候选契约。Codex CLI 与 API key 仅替换模型传输，不维护两套策略。
- 经验更新：trace → 失败/错失机会归因 → 候选策略资料或通用规则 → 冻结局面回放与跨构筑回归 → 小范围实测 → 接受或撤回。单次胜负不自动变为规则；没有版本化经验和复核就不能称为自动学习。

## 实施与验收

1. 先在当前角色闭环：完整培育、解释动作、记录不确定性与失败点。
2. 将路线 guard 的简单结束/等待逐项替换为机制驱动决策；现有好印象专属局部启发式应标记适用范围，不能当成通用评分器。
3. 复用同一决策接口与回放工具，加入另一机制路线及同角色不同卡版本，检查角色资料是否被正确选用、是否污染其他路线。
4. 用规则基线、模型、经验更新后的冻结局面对照评估合法率、识别失败、决策理由、资源使用及实测成绩。只有真实覆盖的路线标记可用。

尚未完成：版本化策略资料检索/更新闭环、跨路线验证、完整选拔与本战通关。当前通用 prompt 和饮料选择只是基础，不能宣称已有自学习系统。
