## 通用定制流程（受控实测）

`HIRO_MECHANISM_CUSTOMIZE=1` 启用完整候选扫描、机制选卡、当前菜单图像比较和严格单级执行，默认仍关闭。角色主数据、准确版本、当前牌组、资源和实际效果是输入，不设角色名称或固定卡牌优先级。CLI 与 API 共用决策接口。

选卡仅授权查看；花费必须另经实际当前/升级后效果图片与已观测价格比较。每次购买只提交一个等级，再读取结果和余额，继续审阅新的菜单。未知状态停止，不调用旧执行器。完整指导列表仅证明当前候选覆盖，不替代持有牌组核验，也不把定制卡基础主数据当实际效果。

实机扫描已验证顶部到底部及返回顶部：18 张卡、9 张可定制、无未知观测或拼接错误。此前一笔 70P 开始手牌定制已核对成功，P760→690。新串联主循环仍待实机验证。回归 1135 passed / 532 skipped；最后驱动修订另跑 9 项通过。

泛化验收须区分当前角色跑通、不同机制路线回放和其他角色实机验证。当前记录用于复盘，不声称已实现自动策略学习；后续策略变化应版本化，在冻结局面比较动作及理由后再实测，避免把单局分数变化解释为因果提升。

跨角色生命周期检查发现并修复：复用 advisor 时，已知 profile 切换到未知/缺失身份现在清空旧档案并保留模型连接；等价 skin ID 保持同一 brain。显式身份模式下，有专用 profile 的角色也附加本帧装备证据，既有档案不再屏蔽准确 item ID 或版本未知状态。

串联实机 r14 已完成全部候选扫描、机制选卡、精确定位并取得ファンシーチャーム+的三个真实预览；购买前因 OCR 将同一选项“コスト値-”读作“コスト値”而停止，无新花费。修复仅在已绑定相同选项 ID 时容忍末尾减号缺失，其他名称、金额、次数和身份仍须一致。三个定制 prompt 补充版本头 1.0，早期 trace 中的 @? 保留原始记录。
